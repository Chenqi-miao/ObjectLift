## 2. 选型与职责说明

Jina CLIP v2负责把图片/视频帧与查询文字编码成可比较向量；Qwen2-VL-2B负责图片描述、标签及视频整体摘要。当前描述不参与搜索排序，标签参与筛选。选择Qwen2-VL与现有依赖兼容，不能沿用旧技术路线中Qwen3-VL候选名称作为已安装模型。

| 方案 | 能解决的问题 | 当前决定 |
| --- | --- | --- |
| 直接图文向量检索 | 不依赖生成描述即可搜索画面 | 当前主线 |
| 描述文本检索 | 使用可读描述作为检索依据 | 待对照评测，存在描述遗漏影响 |
| 两者融合 | 利用视觉和描述两种信息 | 未实现，不能宣称效果更优 |

## 3. 图文检索集成

图片/视频抽样帧编码并保存归一化向量；查询先编码或读取缓存，再按类型/标签筛选兼容向量、计算相似度并合并同视频邻近命中。模型版本、维度不一致时不能混算。

【代码 AL-03】`services/embeddings.py:JinaEncoder.load/image/text`，重点展示本地加载和编码适配；`services/indexing.py:normalize/search`展示校验与相似度计算。每段建议10—25行，完整函数放附件。

【界面截图 AL-04】固定查询、筛选条件、Top结果及原画面对照。至少包含成功样例和典型误检，不能只挑最好结果。

## 4. 内容理解与输出校验

图片使用原生图像输入生成中文描述及最多5个标签；视频最多选取16个有序抽样画面生成整体摘要。视频不含音轨，不等于逐帧完整理解。输出经JSON结构与类别校验，保存状态、结果和版本。

【图 AL-06】图片与视频输入示意：单图生成描述标签；视频抽样序列生成整体摘要。

【代码 AL-07】`services/caption_worker.py:load_model/generate/main`与`services/captions.py:normalize_tags/save`。解释约束输出、无匹配类别和失败处理，不把提示词长度当作算法工作量。

【界面截图 AL-08】原图与描述/标签同框；视频摘要与抽样画面对照。标记AI生成，保留人工复核意见。

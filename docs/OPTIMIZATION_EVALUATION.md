# 优化前后对比计划

记录日期：2026-11-12。状态：已记录，尚未采集统一基线，尚未执行优化。

## 对比规则

1. 每轮改动前记录 Git 提交、未提交差异、依赖版本、模型 revision、硬件/驱动、运行方式、配置、素材清单及 SHA-256。以独立测试库运行，不修改用户实际素材库。
2. 前后使用相同素材、查询、人工相关性标注、操作脚本和参数。性能优化保持模型和输出要求不变；模型/提示词变化单独列为质量实验。
3. 区分冷启动、模型已加载后的首次查询、重复查询缓存命中；区分下载、加载、推理、排队及端到端耗时。固定各项起止时刻，记录后台负载。
4. 耗时测试至少重复 3 次，记录每次结果、样本量、中位数及范围；P95 仅在样本量足够时报告，不能拿三次结果宣称可靠尾延迟。
5. 同时检查资源占用、失败率、输出质量和数据一致性，不能只报告提速。旧版本没有某项能力时记为“新增能力”，不编造百分比。
6. 基线采集后、实现前确定每项验收目标。未采集基线的数值留空标“待测”；既有历史实测仅作参考，不冒充同条件基线。

## 评测素材和任务

- 功能集：固定选择 COCO128 中 20 张图片及 Sintel 示例短片；保存清单，防止每轮换图。
- 批量集：COCO128 全部 128 张；固定处理顺序，统计成功项，不把跳过已完成素材计为吞吐提升。
- 检索质量集：至少 20 条固定中文查询；事先人工标注相关素材和允许的相关视频时间区间，保留具体成功/失败案例。
- 规模测试：先测当前规模；需要更大规模时固定并注明数据来源、画面数及向量维度。复制向量的合成测试只证明计算性能，不证明检索质量。
- 现有纯色图 GPU 测试和动画视频只用于运行验证，不足以代表真实描述质量或普遍检索准确率。

## 各方向的前后指标

| 方向 | 基线/复测指标 | 正确性和代价检查 |
| --- | --- | --- |
| 操作体验 | 导入到首次成功搜索的时间、点击/步骤数、误操作与求助次数、任务完成率；同任务截图/录像和用户反馈 | 同一用户、固定任务；记录熟悉操作带来的练习效应；用户确认流程更顺畅 |
| 批量推理 | 20/128 图总耗时、每图耗时、模型加载次数、吞吐量、峰值显存/内存 | 完成数、失败数、描述质量不退化；批次结束释放显存 |
| 任务调度 | 排队时间、处理中搜索响应/拒绝次数、进度反馈延迟、取消响应时间 | 单 GPU 调度不超显存；取消/中断后可恢复、不重复处理、不丢结果 |
| 环境与启动 | 干净环境安装成功率、人工步骤数、安装/启动耗时、首次运行错误数 | 固定依赖可复现；网络下载耗时单列；缺失模型/FFmpeg 的提示明确 |
| 数据备份恢复 | 备份/恢复耗时、备份大小、恢复成功率 | 原文件哈希、素材数、标签/向量/回收站状态一致；考虑 SQLite WAL 和备份一致性 |
| 测试与 CI | 新工作台关键流程覆盖、自动测试结果、运行时间、人工验收步骤 | 测试数增长不等于质量提升；展示实际防住的回归，离线测试与模型测试分开 |
| Docker 交付 | 构建/启动时间、镜像大小、真实模型推理是否通过 | Linux 路径兼容、GPU 运算、挂载、重启持久化；与 Windows 同输入比较 |
| 检索性能 | 冷/热/缓存命中耗时、读库/编码/排序耗时、峰值内存、不同素材规模 | Top-K 结果一致或解释差异；新增/删除/恢复素材后的索引及时更新 |
| 检索与描述质量 | 前五张至少找到一张的查询比例、按库内正确图片数计算的可找回比例、描述事实错误/幻觉率、标签准确性及失败率 | Hit@5 为至少命中一个人工相关素材的查询占比；可找回比例逐查询计算为找对张数/min(5,库内正确图片数)，然后平均；无标注正例单列、不计分；保留逐查询/逐图片人工判定，不只展示成功样例 |

沿用 ACCEPTANCE.md 中 Top-5 目标 80% 时，应先确认其口径是否为 Hit@5，不能混用可找回比例；按2026-11-12用户确认，Precision@5不再作为本项目评分指标。描述错误判定规则也须在评测前固定。

# 第一轮优化结果：批量描述模型复用

日期：2026-11-12。仅完成本轮范围，其他 TODO 未实施。

## 变化
- 原来逐图启动进程并加载 Qwen；现在一个批次复用一个离线进程，每张结果独立校验、保存，失败继续下一张。批次结束关闭进程；超时/进程退出后下一项可重建进程。
- 全批次持有模型任务锁，避免另一任务插入导致显存竞争；单项描述接口保持原行为。
- 工作台默认展开处理任务，提供“补齐图片描述与标签”入口，明确全库范围及索引/描述用途；不再必须切到诊断页才能批量生成。未实现自动串联导入、取消或完整任务队列。

## 同条件小样本实测
RTX 5060 Laptop 8GB，Python 3.12.16，torch 2.7.1+cu128；模型版本、提示词、输入及生成参数不变。固定 COCO128 排序后的前三张图片，各三轮，每轮独立测试库。

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 三轮总耗时（秒） | 42.85 / 38.48 / 38.20 | 22.29 / 22.35 / 19.83 |
| 中位耗时（秒） | 38.48 | 22.29 |
| 每轮模型加载次数（正常路径代码行为） | 3 | 1 |
| 失败数 | 0/9 | 0/9 |

中位耗时下降 42.1%，约 1.73 倍吞吐；九项输出逐项一致。这是运行方式的小样本对比，不证明描述本身正确，不是 128 图或 P95 结果。顺序执行可能受到系统缓存影响，后续应交错测试更大样本。未采集峰值显存/内存及严格冷启动对照，不宣称资源占用下降。

原始输入哈希和输出：[JSON 报告](benchmarks/caption-batch-2026-11-12.json)。复测：`python scripts/benchmark_captions.py --mode single` 或 `--mode batch`（使用项目虚拟环境）。

## 验证与限制
- 29 项单元/集成回归通过，新增批内失败隔离、忙时拒绝和迭代器关闭后锁释放检查；模型替身测试与上述真实 GPU 测试区分。
- 真实推理结束后未发现残留 caption_worker.py 进程；GPU 总占用包含其他进程，不用它推断本批次峰值。
- 界面回调及页面构建测试通过；尚未完成新版入口的浏览器点击验收，操作时间与误操作率待用户实测。

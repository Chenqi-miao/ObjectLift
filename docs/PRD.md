# ObjectLift v2：视觉素材整理与检索工具
版本：2026-11-06 · 一周 MVP 草案

本方案取代图片转 3D 方向。旧方案保存在 archive/PRD-3D-v1.md。本文件描述待开发目标，不表示已经实现。

## 1. 定位与核心需求
面向个人创作者和学生：导入本地图片与短视频，自动生成描述和标签，用中文自然语言找回素材，并定位视频中的相关画面。
用户记得内容，却不记得文件名和时间点。演示主线：“搜索傍晚街道上的自行车，找到图片或视频画面并打开查看。”

## 2. 时间与资源约束
- 七天，一人主做技术；组员负责素材、查询标注、试用及答辩。
- RTX 5060 8GB、32GB 内存；本地 Windows/WSL2，Git、Docker、VS Code。
- 一个默认素材库、单用户、本地 Web，不增加多库和账号系统。
- 首版测试规模：100 张图片、5 段不超过 4 分钟的视频，最多 1000 个检索单元。这是验收边界，不是已验证的容量。
- 大模型描述和语义检索必须真实运行，替身测试不能冒充模型验收。

## 3. P0 范围
| 编号 | 功能 | 验收行为 |
| --- | --- | --- |
| P0-01 | 批量导入 | 支持 JPG/JPEG/PNG、MP4；逐文件状态；相同哈希不重复入库 |
| P0-02 | 默认素材库 | 托管媒体副本、元数据和缩略图持久化，重启后可浏览 |
| P0-03 | 视频抽帧 | 每 5 秒一帧，保存实际时间戳；不足 5 秒至少取首帧 |
| P0-04 | 自动整理 | 每个画面生成一句中文描述、最多 5 个标签，支持标签筛选 |
| P0-05 | 中文语义搜索 | 返回 Top 10，按图片/视频和标签过滤 |
| P0-06 | 预览定位 | 图片预览，视频结果展示命中帧与时间，点击播放器跳转 |
| P0-07 | 使用素材 | 提供托管原文件下载，不做片段裁切导出 |
| P0-08 | 失败恢复 | 显示进度、错误和重试；重启续处理未完成单元 |

图片上限暂定 20MB，视频 300MB/4 分钟。视频验收限定 H.264 编码 MP4；不承诺所有 MP4 均能在浏览器播放。真实格式、编码、时长都需校验，不能只检查扩展名。

标签采用粗粒度多标签分类，例如人物、动物、建筑、自然、室内、交通、食物、物品；不自动移动原文件。标签错误可通过重试观察，人工编辑器不纳入本周。

## 4. 页面与交互
- 顶部搜索框、导入按钮、入库进度。
- 左侧全部素材/图片/视频/标签筛选，中间素材网格。
- 详情区展示图片或播放器、描述、标签、处理状态和原文件下载。
- 素材列表按文件展示，搜索可以命中同一视频的多个时间点，相邻重复命中合并。
- 未就绪素材可浏览元数据，不能伪装成已参与检索；失败可单独重试。
- 自动描述标为 AI 生成，实际画面作为核实依据。
- 相似度不是准确概率；空库、处理中和低相关结果要有清楚提示。

## 5. 明确不做
3D、目标检测框编辑、实时摄像头、音轨转写、专项 OCR、人物身份识别、复杂动作与前后关系推理、聊天追问、多库、账号、原生移动端、公网发布、目录监控、模型训练、相似图片去重、片段导出。
首版使用批量文件选择，不做文件夹递归导入。

## 6. 文件与数据原则
导入后复制到托管目录，不改动原文件。SHA-256 用于完全相同内容去重。
SQLite 保存元数据、标签和向量；原始媒体、缩略图独立保存。全部业务数据在 data 目录，权重在 models 目录，均排除 Git。
删除/清库界面不在本周范围；提供关闭服务后备份与重建测试库的说明。

## 7. 验收目标（尚未实测）
1. 固定 100 张图和 5 段视频，组员提前写 20 条中文查询及相关素材/视频时间区间，避免针对结果临时修改问题。
2. Top-5 命中率目标 ≥80%：前五个结果中至少一个属于人工相关集合。视频必须命中标注区间；主验收只覆盖抽样帧中可见的场景。
3. 另外测试 5 条无相关素材查询，不能把最近似结果宣称为正确答案；不承诺可靠的未知内容拒答。
4. 已索引 1000 单元、模型已加载时搜索 P95 目标 ≤3 秒，至少 20 次查询；冷启动单独记录。
5. 记录安装耗时、总索引耗时、每帧耗时、显存峰值，不承诺实时入库。
6. 重复导入、损坏文件、部分失败、中断恢复测试通过。
7. 图片与原文件可打开，浏览器视频跳转误差目标 ≤1 秒。
8. Docker 构建、GPU 推理及重启持久化分别实测；Windows 成功不能代替容器验收。

## 8. 七天交付与止损
| 时间 | 交付 |
| --- | --- |
| Day 1 | 20 张图验证中文描述、标签、文本搜图，测速度显存并冻结模型 |
| Day 2 | SQLite、托管导入、哈希去重、阶段状态与恢复 |
| Day 3 | 视频抽帧、时间记录、统一检索单元 |
| Day 4 | 素材网格、筛选、搜索、播放器跳转 |
| Day 5 | 全流程及固定查询集评测，功能冻结 |
| Day 6 | Docker、持久化、异常回归 |
| Day 7 | 演示、报告、课程开发过程整理 |

Day 1 候选模型失败后只做一次明确的较小模型/低分辨率调整。仍失败则提出具体替代方案，不连续耗费数天，不默认产生 API 费用。
时间不足优先减少素材规模和细粒度标签，不加新功能，不静默将语义检索降为关键词搜索。
团队提交物：你负责代码与验证；组员提供素材来源、查询标注、试用记录、演示脚本和 PPT。

# ObjectLift 产品交付文档（初稿）

日期：2026-11-09｜用途：课程项目汇报、研发范围对齐与最终验收准备。

本稿包括需求文档、用户流程、功能优先级、输入限制、验收目标和范围清单六项交付物。优先级与后续安排是建议；实现状态依据现有代码与开发日志，不能代替正式验收记录。

## 交付物一：产品需求文档

### 1. 产品定位与目标

ObjectLift是一款面向学生和个人创作者的本地视觉素材整理与检索工具。核心主张是“记得画面，就找得到”：用户通过中文描述查找图片与视频抽样画面，结合AI描述、标签和统一素材库，完成整理、查找、预览与使用。

产品要解决三个问题：文件命名不能准确反映画面内容；视频需要反复拖动才能找到相关片段；素材缺少统一的描述和分类。项目暂不以多人协作或专业数字资产管理平台为目标。

### 2. 用户场景

| 用户 | 场景 | 用户期望 |
| --- | --- | --- |
| 学生 | 为课程汇报寻找之前收集的配图 | 不记得文件名，也能按画面找回 |
| 个人创作者 | 从图片和短视频中寻找创作参考 | 在一个入口搜索并预览不同媒体 |
| 素材收集者 | 整理不断积累的本地资料 | 识别重复文件、补充描述、按标签浏览 |

这些是拟定的目标场景，尚不能作为用户调研结论或效率提升数据。

### 3. 功能需求

| 编号 | 用户需求 | 功能要求 | 当前状态 |
| --- | --- | --- | --- |
| FR-01 | 一次导入多份素材 | 批量选择文件，托管副本，逐项显示结果 | 已实现，完整验收待补 |
| FR-02 | 避免重复收录 | 按文件内容哈希识别完全重复素材 | 已实现，有回归记录 |
| FR-03 | 随时浏览已收录素材 | 展示网格、预览和元数据，重启后保留 | 已实现，有回归及部分界面记录 |
| FR-04 | 用中文描述找素材 | 建立视觉索引，按图文相似度返回结果 | 已实现，检索质量待评测 |
| FR-05 | 找到视频内的画面 | 抽帧、保存时间戳、展示命中帧及定位入口 | 已实现，浏览器定位精度待验收 |
| FR-06 | 快速了解素材内容 | 图片生成描述和标签，视频生成整体摘要 | 已实现，单样本真实推理通过 |
| FR-07 | 缩小查找范围 | 支持类型、标签和文件名等筛选入口 | 已实现，完整交互待验收 |
| FR-08 | 处理失败后继续使用 | 显示阶段与错误，支持重试和中断状态恢复 | 已实现，完整异常验收待补 |
| FR-09 | 使用找到的素材 | 查看详情，下载托管原文件 | 已实现，部分界面记录通过 |
| FR-10 | 撤销误移除操作 | 回收站软删除与恢复，隐藏已移除素材 | 已实现，有回归记录 |

FR-06的图片标签支持未完成/失败项批量补齐。视频摘要不等于逐帧描述；视频逐帧描述和标签不计入当前完成范围。

### 4. 非功能需求

- 本地性：模型推理使用本地权重，不向云端推理服务发送素材；首次安装和下载模型可以需要联网。
- 数据完整性：导入不改写用户源文件；重复、失败和恢复操作不得产生错误的可用素材记录。
- 可解释性：展示画面、时间、AI描述和处理状态，不把相似度当成正确概率。
- 可维护性：记录模型版本，保留运行及测试说明，模型版本不兼容的向量不得混算。
- 可用性：耗时任务有反馈，失败可定位；单个文件失败不阻断整个批次。
- 可交付性：本地启动流程可复现；Docker GPU、持久化和备份恢复必须单独实测后才计为完成。

## 交付物二：用户流程

### 1. 首次使用与素材入库

进入首页 → 打开工作台 → 选择图片或短视频 → 点击导入 → 查看每个文件的成功、重复或失败提示 → 在素材库浏览已成功导入的文件。

导入成功只表示文件已经入库，不等于已经完成索引或描述生成。

### 2. 让素材可以检索

手动点击建立索引/重试 → 系统处理图片与视频抽样帧 → 查看进度 → 就绪素材进入语义搜索范围。

失败项显示错误并可重试；模型繁忙时提示等待。界面不得把未就绪素材伪装成搜索候选。

### 3. 按需生成内容说明

选择图片 → 生成描述与标签 → 查看结果；或在批量补齐入口处理未完成/失败图片。

选择视频 → 生成视频摘要 → 查看基于抽样画面的中文说明。此流程不是语义检索的必经前置步骤；索引与描述承担不同任务。

### 4. 查找并使用素材

输入中文描述 → 提交搜索 → 结合类型/标签筛选 → 查看相关结果 → 点击详情 → 图片预览或视频命中时间与定位入口 → 下载原文件。

没有合适结果时，调整描述或筛选条件。系统不保证每次查询都有相关素材，不能把最近似结果称作正确答案。

### 5. 删除与恢复

选中素材 → 移入回收站 → 从正常列表和检索结果排除 → 进入回收站 → 恢复 → 素材重新可用。

原文件与已有索引保留，不释放磁盘空间。模型任务运行期间按当前规则拒绝移除/恢复，避免并发状态冲突。

### 6. 关键异常分支

| 触发条件 | 用户应看到的结果 | 后续动作 |
| --- | --- | --- |
| 文件超限、格式不支持或损坏 | 指向该文件的原因，不影响其他文件 | 更换文件后重试 |
| 完全重复文件 | 已入库提示，不重复创建记录 | 使用已有素材；回收站内素材先恢复 |
| 索引或描述生成失败 | 失败阶段、错误和重试入口 | 修复环境或重试 |
| 任务执行中应用退出 | 重启后中断项可重新处理 | 手动触发重试；不承诺后台自动续跑 |
| 空素材库或筛选后为空 | 清楚的空状态 | 导入素材或清除筛选 |

## 交付物三：功能优先级

优先级按最终交付重要性划分，不代表开发先后，也不表示功能尚未开发。P0缺失将影响核心交付；P1用于增强整理体验；P2为后续候选。

| 优先级 | 功能或任务 | 安排理由 |
| --- | --- | --- |
| P0 | 批量导入、去重、持久化素材库 | 产品的数据基础 |
| P0 | 图片及视频帧索引、中文语义搜索 | 核心产品价值 |
| P0 | 类型/标签筛选、图片描述与标签、视频摘要 | 当前产品承诺的整理能力 |
| P0 | 预览、命中时间、原文件下载 | 完成查找与使用闭环 |
| P0 | 状态反馈、失败重试、恢复能力 | 保障实际使用和数据可靠性 |
| P0 | 固定查询集评测与完整浏览器验收 | 证明质量，而非仅证明接口存在 |
| P0 | 启动说明、备份恢复、计划内Docker GPU验证 | 完成可复现交付 |
| P1 | 已接入的回收站恢复、查询缓存、预热和批量补齐 | 提升效率和管理体验，应回归验证 |
| P1 | 导入后自动调度、窄屏体验完善 | 待确定设计后补充，不阻挡当前手动主流程 |
| P2 | 描述文本检索与混合检索 | 先评测收益再决定实现 |
| P2 | 视频逐帧描述与标签 | 范围和成本待确认，不计当前已完成 |
| P2 | 长视频自动切片 | 已记录并明确暂缓 |
| P2 | 永久删除与回收站清空 | 需独立设计数据删除与确认流程 |

本轮优先完成P0验收，不因新增P2功能推迟核心交付。新增自动化能力需保持手动操作可理解、可重试。

## 交付物四：输入限制与运行条件

| 项目 | 当前约束 | 用户提示或说明 |
| --- | --- | --- |
| 图片格式 | JPG/JPEG/PNG，实际内容需可解码 | 不只依靠扩展名判断有效性 |
| 图片大小 | 每张不超过20 × 1024²字节 | 界面称20MB，实际按二进制阈值判断 |
| 图片像素 | 宽×高不超过40,000,000 | 超限需缩小后重新导入 |
| 视频格式 | MP4容器、H.264视频编码 | MP4扩展名不代表所有编码都支持 |
| 视频大小 | 每段不超过300 × 1024²字节 | 界面称300MB，实际按二进制阈值判断 |
| 视频时长 | 大于0且不超过240秒 | 当前不支持自动切片绕过时长限制 |
| 视频画面尺寸 | 宽×高大于0且不超过40,000,000 | 仍受解码耗时及设备性能影响 |
| 视频抽样 | 约每5秒一帧，记录实际时间戳 | 不承诺覆盖短事件 |
| 视频摘要 | 最多16个有序抽样画面 | 不含音轨转写，不等于逐帧完整分析 |
| 导入方式 | 批量文件选择 | 不承诺文件夹递归导入和目录监控 |
| 查询 | 非空文本，重点验证中文自然语言 | 不宣称已评测全部语言或复杂推理能力 |
| 模型任务 | 串行调度，本地模型就绪后处理 | 不承诺多用户并发和实时批量处理 |

运行需要Python应用环境、兼容模型依赖、已下载权重及FFmpeg/ffprobe。已有RTX 5060 Laptop 8GB实测记录，但这不是经验证的最低配置；CPU检索链路有记录，不代表所有功能和性能均在CPU环境完成验收。当前没有经验证的批量文件数量或总库容量上限，100张图片、5段视频、1000检索单元是拟定验收规模。

## 交付物五：验收目标与方法

### 1. 验收组织

验收前冻结代码版本、模型版本、环境和素材清单。记录每项“通过/失败/未执行”及证据位置；存在失败项时记录复现步骤、影响和修复负责人，不以“功能已写完”代替通过。

| 编号 | 验收对象 | 通过条件 | 验证办法 |
| --- | --- | --- | --- |
| AC-01 | 导入与去重 | 合法文件可入库；重复文件不新增；非法文件单项报错 | 混合导入合法、重复、损坏与超限文件 |
| AC-02 | 数据持久化 | 重启后素材、元数据及就绪索引保留 | 记录导入前后与重启后的数量和抽样文件 |
| AC-03 | 视频抽帧 | 短于5秒视频有首帧；时间戳可对应原视频 | 使用已知时长与内容的测试视频核对 |
| AC-04 | 描述与标签 | 真实模型生成有效说明与合法标签；失败可追踪重试 | 代表性图片与视频逐项检查，记录错误类型 |
| AC-05 | 检索相关性 | 20条固定相关查询的Top-5命中率目标≥80% | 先人工标注相关集合，再评测，禁止看结果后改题 |
| AC-06 | 无相关查询 | 不把近似结果标成正确或确定答案 | 另设5条无相关查询，检查展示和措辞 |
| AC-07 | 筛选与相邻合并 | 类型/标签符合条件，邻近视频命中按规则合并 | 构造可区分的图片/视频帧标签和时间 |
| AC-08 | 搜索性能 | 已索引1000单元、模型已加载时，查询P95目标≤3秒 | 至少20次查询，单列未缓存热查询、缓存查询与冷启动 |
| AC-09 | 浏览与定位 | 图片可预览，视频可播放，跳转误差目标≤1秒 | 浏览器实际操作，比较目标时间和播放器定位结果 |
| AC-10 | 下载 | 托管原文件可下载，内容与导入原件一致 | 下载后打开并比较哈希 |
| AC-11 | 失败恢复 | 重试不重复创建已完成单元，中断项可恢复处理 | 制造失败/中断后重启和重试，核对记录 |
| AC-12 | 回收站 | 移除后不参与列表/统计/搜索，恢复后重新可用 | 使用专用测试素材，检查文件和索引保留 |
| AC-13 | 部署交付 | 本地启动可复现；容器GPU推理、挂载持久化与备份恢复分别通过 | 按交付说明从环境准备到重启恢复完整执行 |

Top-5命中率定义为：前五个结果至少有一个属于预先标注相关集合的查询数÷有效相关查询总数。视频命中须落在标注时间区间。主验收覆盖抽样帧可见场景，不据此宣称能检出未抽样短事件。

性能计时应明确是服务端查询还是浏览器端到端；两者分开记录。描述质量暂不虚构准确率目标，先记录遗漏、错误对象、主观推断和分类错误，形成可审阅的样例集。

### 2. 当前证据与待补工作

已有开发日志记录27项回归通过、真实FFmpeg抽帧、Jina检索与Qwen图片/视频推理、部分浏览器操作。本稿编制没有重跑测试；这些历史记录不能替代以上完整验收，80%、3秒P95和1秒定位误差均为待验证目标。

## 交付物六：范围清单

### 1. 本轮交付范围

- 单用户本地Web与一个默认素材库。
- 指定格式的图片/短视频托管导入、去重、预览、持久化。
- 图片与视频抽样帧语义索引，中文搜索与类型/标签筛选。
- 图片描述、粗粒度标签、未完成图片批量补齐、视频整体摘要。
- 原文件下载、状态与错误反馈、重试、回收站恢复。
- 产品说明、运行说明、模型说明、测试证据、演示素材和交付检查。

### 2. 已有入口但仍需验收

- 视频播放器跳转和定位精度。
- 完整浏览器流程及窄屏表现。
- 真实素材集的检索质量与性能。
- 中断、异常和恢复在完整使用流程中的表现。

### 3. 待完成的交付工作

- 更新落后的文档状态并形成正式验收记录。
- 补齐并验证Docker新版模型依赖、GPU推理及持久化。
- 实测备份恢复，准备可复现演示与固定素材集。

### 4. 后续候选，不计入当前完成成果

- 导入后自动处理、视频逐帧描述标签、描述检索或混合检索。
- 长视频切片、永久删除、清空回收站。

### 5. 明确不纳入本轮

3D生成、自动目标检测和去背景、账号与多人协作、多库管理、公网发布、模型训练、人物身份识别、音轨转写、专项OCR、复杂事件推理、视频片段导出、目录监控和原生移动端。

## 后续执行顺序与验收口径

### A. 先冻结功能用例，补自动边界（第一批）

将每个组合拆成独立TC，字段为：ID、需求、层级、输入、前置、步骤、预期、实际、证据、状态、缺陷。现有29项是回归方法数量，不自动等于P0数量。按导入/处理/搜索/定位/恢复主流程确定P0清单后统计通过、失败、未执行、阻塞四项，禁止动态删掉失败用例。

补字节阈值以下/相等/以上、短于5秒与真实240秒视频、不同编码/容器、损坏与合法文件混合导入；再测处理中退出与重新启动。浏览器通过状态独立于服务层。

### B. 冻结数据与查询，做质量和性能（第二批）

- 先用COCO128的人工物体标签准备20条有相关素材查询、5条无相关素材查询；保存文件SHA-256、相关ID及中文映射，先核对标注再运行。该128图实验是初评，不冒充原计划100图+5视频的综合验收。
- Hit@5在20条正查询上统计，至少16条命中才达到80%；逐条保存前五结果。无相关查询单列误报与拒绝表现，不记入Hit@5分母。开发集和最终测试集分开，不能先调到通过再宣称泛化。
- 综合验收补齐5段有人工相关时间区间的视频。单段Sintel仅可验证流程，不能支撑普遍视频检索质量。
- P95先准备固定1000个真实视觉单元，记录其构成；模型预热后至少100条不同查询分多轮测，缓存命中另测。排序耗时样本，以最近秩法第ceil(0.95*n)个为P95；同时报告中位数、样本数、失败数、冷加载和端到端时间。仅有128图的结果单列规模，不判1000单元指标达标。
- 描述按对象/数量/动作错误、遗漏、无依据推断和标签错误人工复核；输出格式通过不代表语义准确。

### C. 浏览器闭环和定位（第三批）

从导入、建立索引、搜索、选中结果、下载到回收站恢复完整操作，采集真实截图。视频至少3个样片、各5个可达时间点，记录目标秒数、seeked后currentTime、绝对误差、首次加载或缓存状态及失败原因；每次均≤1秒才判这一组通过。保留录屏和时间JSON，确认对应画面、不是只看URL参数；抽样帧时间误差与播放器seek误差分开。

### D. 部署与恢复（第四批）

补模型依赖和Linux本地路径后再构建项目容器，验证真实Jina/Qwen GPU推理、挂载与重启持久化。基础nvidia-smi通过不替代该项。备份先采用停止写入的范围，使用SQLite backup API加媒体副本，恢复到新目录；补非空标签、视频摘要、向量、回收站与哈希核对。在线备份需另设计一致性协议，不能拿此离线演练代替。
